# 患者の顔モザイク

新規の動画編集で患者の顔が映る場合は、この手順でモザイクを標準適用する。今回のユーザーによる対象・範囲・方法の具体指定を優先し、完成済みの別案件には遡及しない。通常の適用のたびに承認を求めず、誰を対象とするか判断できない場合だけ確認する。

ぼかしとモザイクは別の処理である。見本がぼかしでも、今回の指定がモザイクなら画素をブロック化する効果を使う。「効果を追加できた」ことと、「動く顔を全区間で隠せた」ことを区別する。

## 1. 顔の露出区間を特定する

今回の採用区間を最初から最後まで確認し、患者の正面・横顔・顔の一部、画面への出入り、鏡や窓などの反射を拾う。背景の掲載写真・ポスター・モニター内に写る顔も見落とさず、対象に含めるか記録する。小さい写真だから確認不要とは扱わず、人物の役割や対象範囲が判断できないものは未確認として分ける。開始・中間・終盤の抜粋だけで顔の有無を判定しない。顔が再び現れる場合は、その区間も記録する。映像から確定できない人物の役割を服装などで決めつけない。

原素材に加えて、実際のトリミング・回転・拡大縮小・配置・切替を反映した完成画面で対象を確定する。別の区間で同じ素材を再利用する場合も確認する。

案件内の作業記録には、素材と使用範囲、タイムライン上の最初の露出フレーム・最後の露出フレーム、患者と反射の対象、顔の動き、確認した画面を残す。半開区間を使う場合、終了は最後の露出フレームの次とする。秒数の丸めで最初・最後の1フレームを落とさない。

採用元映像は顔がないと判断した区間も全フレームを確認し、実際のフレーム時刻（PTS）・番号・確認枚数・未確認の有無を記録する。採用境界の隣接フレームも確認し、トリム時刻の丸めによる取りこぼしを防ぐ。元映像での顔・反射の有無や予定範囲への収まりの確認は、完成出力でのモザイクの描画・強度の確認とは別の記録にする。

## 2. 現在の機能と座標を確認する

使用中のChatCutホストの基本スキル・ツール定義を読み、ネイティブの局所モザイク、適用先、範囲形状、位置と大きさ、強度、時間変化を設定できるか確認する。追従・キーフレーム機能やAPIが未提供なら、利用できるものとして呼び出したり、追従済みと報告したりしない。

既存映像の子効果など、後で編集・解除できるネイティブ構成を優先する。字幕や別の人物までまとめて隠さないよう適用対象とレイヤー順を確認する。外部レンダリングで焼き込む代替は、使用中のホストの規約と今回の許可に従い、無断で切り替えない。対応できない場合は不足機能と未処理区間を明示する。

**`builtin:fx-local-mosaic`の実測メモ：** ある制作環境の実合成では、`center_y`が下端を0とする向きだった。元画像の上端を0とする正規化座標と同じ座標空間・尺度なら、`center_y = 1 - y`が対応する。ただし他の効果、ホスト、解像度、トリミング、回転、レイヤー変換へ無条件に転用しない。使用中の設定定義を読み、既知の顔位置で試し、実合成上の上下・左右・中心・幅・高さを確かめてから他区間へ適用する。

## 3. 必要な範囲だけを覆う

顔全体に、動きと輪郭の見落としを防ぐ必要な余白を加える。目・鼻・口だけの小さな範囲や、正面だけに合う範囲で済ませない。一方で、施術者、手、検査・施術部位、字幕を不要に隠す大きさにしない。反射した患者の顔は別の対象として扱う。

- **固定範囲：** 採用区間の全動作を内包し、余白も過大にならない場合だけ使う。顔がほぼ静止して見える一枚だけで決定しない。
- **動く顔：** 対応機能があれば、方向転換、距離や向きの変化、出入りに合わせて位置・大きさのキーを置く。キー間の補間も検証する。
- **短区間への分割：** 適切なキーを使えない場合に、現在の機能でモザイクの適用範囲を短く分けて調整する。元の尺や音声を切らず、区間間に空白や不要な二重処理を作らない。

一時的に手や他の物で顔が隠れても、顔が戻る直前・直後を含めて漏れを確認する。動きを追えない状態を、画面全体に近い過大な範囲で埋め合わせない。

## 4. 出力画面で強度を較正する

モザイクの強度・ブロックの大きさは、顔の画面上の大きさと最終出力解像度に合わせる。プレビューが小さいため見えないだけ、または肌が少し粗くなっただけの状態を合格にしない。今回の1080幅など、実際の出力サイズで顔の特徴が読み取れないか、周囲を余計に壊していないかを確認する。

強度の数値の意味は効果ごとに異なる。過去の案件の位置・幅・高さ・強度をそのまま既定にせず、特定の数値だけで匿名性を保証しない。強めた後も、顔の輪郭や横顔が範囲の外へ出ていないかを別に確認する。

## 5. 全露出フレームと保存状態を検証する

顔が露出する各区間は、完成合成または現在の修正版から出力した動画で、**全フレームを漏れなく順に確認する**。連続再生で動きを見たうえで、フレーム送りや順番の分かる連続画像で確認する。等間隔の抜粋画像だけで合格にしない。確認手段が全区間をカバーできなければ、確認済み範囲と未検証範囲を分けて残す。

音声修正で映像・モザイクを変えていない場合は、[修正版の全フレーム比較](provided-narration.md#修正版の確認と保存)を使える。確認済みの旧版と今回の出力を比較し、顔領域を含め不変と確認できた部分だけ既存の確認記録を再利用する。差のある部分と前後は改めて表示して確認する。設定値が同じという理由だけで確認を省かない。

特に、最初・最後の露出1フレーム、カットの前後、効果の開始終了、短区間の接続、キーフレーム間、画面端への出入り、横顔、反射、拡大やトリミング後の範囲を確認する。切替中に複数の顔が残る場合も、それぞれを覆う。

出力の確認範囲はデコード後のフレーム番号で記録し、元映像の番号や確認枚数をそのまま転記しない。連続画像を使う場合は間引き・欠落がないことを照合し、全画面の確認に加え、縮小一覧では読めない顔の特徴を原寸相当の切り出しで確認する。確認した出力の版とファイルを識別し、再書き出しや採用範囲・トリミング・モザイク変更後へ旧結果を自動で引き継がない。

修正後は現在のプロジェクト・タイムライン・映像item・効果の保存IDと適用範囲を再取得して照合する。古い状態のプレビューが疑われるときは保存済み設定を読み直し、編集画面を再読込して同じフレームを再確認する。見た目が更新されないことだけを理由に効果を重複追加しない。

変更前後で映像の順序・使用範囲・再生速度・全尺、音声、字幕の文字と表示時刻を照合する。顔モザイクだけの修正で、別の編集内容を変えない。

MP4を渡す場合は[ローカル保存への引き渡し](local-delivery.md)に従い、修正後の保存状態を使った出力か確認する。確認用の旧MP4を修正版として渡さない。クラウドや有料処理へ無断で切り替えない。

## 6. 結果と共有可能な知見を残す

報告では、対象区間、固定範囲・キー・短区間分割のどれを使ったか、実合成／MP4のどちらで確認したか、全露出フレームの確認範囲、未検証事項を区別する。設定成功やユーザーの完成承認を、実施していない追従試験・音声確認・書き出し確認へ広げない。

0.7.1の根拠となる1制作事例では、ネイティブの局所モザイクを使い、3区間とその境界の連続219フレームをlocal/browser経路のMP4で確認した。`center_y`の向きも実合成で確認した。この219フレームは前景の患者顔と3マスクの境界を確認した範囲であり、他案件の必要確認数ではない。背景の掲載写真に写る人物の患者該当性は未確認で、この漏れなしの評価に含めない。音声込みの全編再生、動く顔へのキーフレーム追従、他ユーザー環境での一連の試験は未検証である。

共有ライブラリには再利用できる手順と確認範囲だけを保存する。個人のファイルパス、案件ID、患者画像、案件固有の位置・強度は含めない。
