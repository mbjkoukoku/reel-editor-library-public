# 公開ライブラリから同じ依頼内で始める

配布元は `https://github.com/mbjkoukoku/reel-editor-library-public`。このライブラリの取得にGitHubの招待やログインは不要。CodexとChatCutの本人の利用資格・認証・端末上の操作許可は別に扱う。公開リポジトリを取得できることと、動画生成が無料であることを混同しない。

## 初回と更新

利用者がコピーしたA07依頼文には、初回のライブラリ設定も含まれる。設定専用の別プロンプトを要求せず、次を担当側で進める。

1. 導入済みの `reel-editor` の版・配布元を確認する。同じ共有元なら更新し、別の個人版やローカル変更を見つけた場合は重複導入・上書きを避ける。作業中の別案件は更新しない。
2. 公開元の `README.txt` と `.agents/plugins/marketplace.json` を読み、現行のCodex機能で導入する。CLIが使える環境の手順は以下。実行ファイルが見つからない場合は、利用可能な公式プラグイン画面を案内し、存在しないボタンやコマンドを作らない。

   ```text
   codex plugin marketplace add https://github.com/mbjkoukoku/reel-editor-library-public.git --ref main
   codex plugin add reel-editor@reel-library
   ```

   同じ公開URLのmarketplaceが登録済みなら追加ではなく、`codex plugin marketplace upgrade reel-library` で更新してからインストールする。旧非公開URLで登録済みの場合、同名を別URLで追加すると競合する。現在の登録先・変更有無を確認し、`codex plugin marketplace remove reel-library` で旧配布元の登録を外してから、上記の公開URLをaddする。これは配布元の登録変更であり、動画プロジェクトや個人プラグインを削除する指示ではない。以前の作業ファイルを削除したり別プラグインを二重導入したりしない。現行CLIのヘルプ・実行結果を確認する。認証エラーを見て直ちに利用者へGitHub招待を要求せず、公開URLと接続・取得結果を切り分ける。
3. 取得したプラグインの `skills/reference-video-edit-library/SKILL.md` と、今回選択したパターンの資料を実際に読む。A07なら `a07.md`、`a07.json`、`a07-approved-profile.md` と `assets/a07/README.md` を使う。ファイルが読めない場合に読了したと装わない。
4. この依頼内では取得したファイルを直接参照して台本作成へ進める。新しく導入したスキルの自動発見だけに依存せず、LPの再提出や新しいチャットの作成を機械的に要求しない。ホストが実際に再起動・新規チャットを必要とする操作は、その時点で必要な手順だけ案内する。

## 利用者の次の操作を一つにする

最初はLPから台本と場面表を出す。ChatCut、フォント、患者役素材は台本作成の前提にしない。台本確認後の次の操作は「施術者・院内の素材動画を同じチャットへ送る」。すでに届いた素材や承認済み台本を再要求しない。

編集段階に進んだら、現在接続されているChatCutを確認してからそのホストのスキルに従う。別アカウントの認証や有料プランを共有したとは扱わない。接続できていればインストールを案内しない。初回のアプリ導入・本人ログイン・ホストの承認操作が必要な場合だけ、本人が行う操作を一つずつ示す。設定の許可を有料生成の許可へ拡張しない。

文字は同梱フォントを現行レンダラーへ登録し、78px／104px等の承認値と実字形で確認する。利用者にフォントを検索・購入させる前に同梱資産を確認する。承認済み台本と必要素材がそろえば編集へ進み、意味を変えない改行やトリムごとに確認を挟まない。

導入完了はプラグイン名・版・読めたA07資料で確認する。共有元の読み取り、導入、動画の合成、音声の試聴、MP4保存を別々に記録し、導入確認だけで別人の完成動画まで検証済みとしない。
