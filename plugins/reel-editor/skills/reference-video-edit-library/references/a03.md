# A03：施術風景・縦書きテロップ

主見本は「0719(1).mov」。実際の相談・検査・施術・再検査を見せながら、別に進む訴求・説明テロップを重ねる。映像中の会話を字幕化する形式ではない。今回の指定は全音声なし。既存A01/A02の音声先行・横組みの手順へ切り替えない。

## 最初はテロップ台本だけ

[caption-only.md](caption-only.md)を使う。[画面原文](a03-script-reference.json)を土台に、LPと異なる院名・地域・料金・条件・施術方針だけを必要最小限に差し替える。見本の順番・大枠・語り口を保つ。原文にある症状の原因や効果・患者の所見も見本店舗の説明であり、新店舗の事実として自動採用しない。LPや提供情報で確認できない箇所は、確認事項と変更案を台本表に示す。

利用者には区間番号、見本テロップ、今回のテロップ（改行）、変更理由・確認事項の表を提示する。縦書き／横書きと同時表示・赤い強調を伝える。読み上げ用原稿は不要。この時点では素材やChatCutを前提にせず、台本確認後に同じタスクへ素材動画だけを送るよう案内する。LPがなければ原文の分析は進め、今回のLPまたは店舗情報を受け取ってから新店舗の台本を確定する。

## 参照資料と確認範囲

[a03.json](a03.json)は30fpsの開始を含む・終了を含まないフレームで記録。720×1280、216.6秒（6498フレーム）の原見本には4つの大きな映像区間と37文字レイヤー、35表示グループがある。文字は縦28・横9。総尺は固定しない。1080×1920などへ変更する場合は比率を保って配置・文字・影を比例させ、実画面で確認する。

`cues[].referenceFrame`に対応する35枚の見本画像を同梱している。別のPCでも文字の構成を比較できるが、新店舗の完成動画の素材として使わない。`referenceText`は比較用原文であり、承認済みの新店舗原稿ではない。

対応するCapCutデータから全37レイヤーの時刻・書体ファイル・太さ・大小・配置・改行・有効な影設定を抽出し、原MOVの全表示グループの中間画面、43組の切替前後、映像カット前後と照合した。後から更新された可能性のあるドラフトの全設定をそのまま採用しない。「検査中...」は実映像では「検査中」なので、原文は実映像を優先した。現ドラフトにある顔ぼかしは原見本で確認できず、既定として加えない。

この記録は分析済みの参照仕様であり、新素材でのChatCut描画・音声なしの書き出し検証はまだ行っていない。設定の存在を完成・再現成功と呼ばない。

## カットとテロップを独立して配置する

1. 台本が決まったら、今回の素材の内容と使用区間を実際に確認する。順序は相談→立位で評価→仰向けで検査・施術→施術後の再検査→説明・案内を基本に、素材の元の流れを大きく変えない。番号付き素材は順序の手掛かりにする。施術者・患者・施術の手元が見える区間を選ぶ。
2. 見本のカットは0–715、715–4695、4695–5308、5308–6498フレーム。長い連続区間内の姿勢変更やカメラ移動を、全部別カットと解釈しない。今回の素材では場面の切れ目と読む時間に合わせて尺を調整する。音声を基準とするフィラー・無音カットはしない。見本の無字幕区間も一律には埋めない。
3. 承認済みテロップの順番・大枠は保つ。訴求文を映っている動作の実況へ書き換えない。ただし「検査中」「施術後」「もう1度チェック」などの場面ラベルや前後の所見は今回の実場面へ合わせる。足の使い方を説明する文に対応する場面がなければ、文字を誤った映像へ重ねず、その部分の変更を相談する。
4. 映像区間とテロップ区間を独立したデータとして管理し、現在のChatCutツールで編集可能なタイムラインへ置く。文字の切替をすべて映像の切替にそろえない。g11の本文＋「足」、g17の「検査中」＋「しっかり評価！」は独立レイヤーで同時表示する。元見本のg17→g18の10フレームの残留重なりは観測記録であり、新しい文字で読みにくい重なりを強制する指定ではない。
5. 全素材をミュートする。ナレーション・BGM・効果音を追加しない。ASRはテロップ生成に使わない。最後まで実映像を保ち、黒い末尾や文字の切れを作らない。

`executionRoute: native_independent_overlays`はこのスキル内の処理分岐名で、ChatCutのAPI名ではない。既存の`timeline_plan.py`は横組み・映像連動の計画用で、A03を安全に処理できないため明示的に拒否する。実在しないA03対応コマンドやAPIを創作せず、利用環境のChatCut基本スキルと現在のツール定義に従って配置する。

## 字体・大きさ・配置・影

本文は「ヒラギノ角ゴシック W6.ttc」、強調はW7、価格はW8と対応ドラフトから分かっている。TTC内のface番号は指定されておらず、候補のPostScript名を`typography.fonts`へ記録している。ファイル名と太さの特定と、描画するfaceの完全一致は区別する。利用者の環境で使えるフォントを確認し、同じ原文の合成画面を見本画像と比較してface・字面・幅を選ぶ。フォントファイルは配布していない。

`cues[].originalCapCut.activeStyles`には、文字範囲ごとのサイズ・白／赤・影がある。`layout`には縦横、字間・列間、`clip`には拡大率・位置がある。これらはCapCut固有単位であり、font-sizeやshadow blurのCSS px値へそのまま代入しない。ドラフトキャンバス1080×1920と書き出し720×1280の違いも考慮し、白い字面の幅・高さ・中心、列間、影の広がりを合成画像で較正する。旧トップレベルの`has_shadow`等ではなく、有効なスタイル内の影を使う。

縦書きは右から左へ列を進め、各列は上から下へ読む。原文の改行は列の区切り。日本語の句読点・括弧・感嘆符の向きと位置を見本に合わせる。長方形の横書き全体を90度回す方法では再現できない。`glyphs.py`のcmap字形・横送り値だけを使って単純に縦積みすると、縦用字形や句読点の配置が欠けるため、その出力だけで縦組み検証済みとしない。現在のレンダラーが対応する縦書き、または縦用字形置換・位置調整を行う描画経路で全字を確認する。Motion Graphicを使う場合は、その環境のMGスキルに従って編集可能に配置する。

基本は白い字と広がりのある黒い影。「治らない原因」「動きのクセ」に赤い強調がある。終盤の3テロップは赤い発光。図形の赤い足の説明線は対応する2区間で2本ずつあり、今回の足の位置に合わせて調整する。説明線を根拠のない位置へ貼らない。表示は基本的に静止文字の瞬時切替で、見本にない跳ね・ズーム・タイプライターを追加しない。静的な発光を動くアニメーションと誤認しない。

## 文字修正と完成確認

文字の修正は区間キーを維持し、該当レイヤーの全文と描画を更新する。映像の採用区間・元音ミュート・テロップ開始終了・表示方向を保ち、範囲で指定する赤文字の索引も新しい文に合わせて更新する。文字の増減で必要な字形と縦横のサイズを再確認する。`text_revision.py`は横幅用のためA03には使用しない。Transcriptの単語削除で誤字を直そうとしない。SVG等の字形方式ではテキスト修正にCodex経由の再描画が必要な場合がある。

全35グループ相当の合成画面と切替、複数レイヤー、赤文字・発光・説明線・最初と最後を確認し、全編を連続再生する。読める時間・画面外への文字切れ・施術の流れ・無音を確認する。利用者へは実際に確認した範囲と残る違いを伝える。MP4を求められた場合は、[Desktopでのローカル保存](local-delivery.md)を基本にする。
