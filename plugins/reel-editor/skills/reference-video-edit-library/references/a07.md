# A07：患者目線・1日Vlog

0.9.0で追加。0.10.5では[完成承認版の制作基準](a07-approved-profile.md)を追加した。新規制作は `a07.json.productionDefaults` の文字サイズ・行間・BGM／効果音・施術後の流れを優先し、以下の原見本の観測値と区別する。「A7」もA07として扱う。見本は `ex患者vlog2.mov`。朝の生活・家事、院を知るきっかけ、来院・相談・施術、日常へ戻る場面を、時刻と短い画面文でつなぐ。**患者役の素材を利用者の必須提出物にせず、こちらで準備する。1本の中では同じ人物に統一し、別の動画を作るときは人物を変える。** 原見本の実患者や施術者を新しい店舗の映像として流用しない。

## 最初の入力と台本確認

1. 依頼文と今回のLP／ホームページ、または利用者が確認した店舗情報を受け取る。今回が見本登録だけなら、LPなしで仕様を登録できる。
2. **まず画面テロップの台本と場面表を出し、確認を待つ。** 見本のVlog構成・短い時刻表示・文字デザインを基準にする。院名・地域・施術者の説明・アクセスなどは今回の事実へ変える。読み上げ台本、患者本人の発話、AI音声は前提にしない。
3. 場面表に「画面文／根拠または架空ストーリー／必要な映像の開始状態→動作→終了状態／素材の担当／既存素材で使えるか／仮の長さ」を書く。担当は、利用者が用意する施術者・院内映像と、こちらが準備する患者役映像へ分ける。院SNSの画面を挿入するなら今回の確認済み画面にし、なければ省略・別表現へ置き換える。
4. 台本確認後は「施術者・院内など、用意できる素材動画を送ってください。患者役の映像はこちらで準備します」と案内する。患者素材やAI音声を必須提出物として求めない。承認済みの台本や予算がある場合はその承認を引き継ぐ。

`executionRoute: patient_vlog_with_sourced_cast` はライブラリ内の分岐名で、ChatCut API名ではない。A04の逐語字幕、A06の発話要約、A05の実患者の前後比較へ自動で切り替えない。固定cueの伸縮や一般字幕用 `timeline_plan.py`・`text_revision.py` へ通さず、現在のChatCutホストで使用できる独立したテキスト・装飾・素材として編集する。

## 患者役の素材をこちらで準備する

**同じ1本では同じ架空人物、別の1本では別の人物**という今回の利用者指定を使う。同じ人物の家事・移動・日常をつなぐため、場面ごとに別人を生成しない。髪型・顔・体格・衣服などを確認できる承認済みの参照画像または動画を、その作品の基準にする。文字の説明だけで人物が一致したと判断せず、完成映像を比較する。

- まず場面と必要尺を具体化し、利用可能な素材と生成が必要な部分を決める。動画生成は現在のホストの基本・動画生成スキルと実在するツールで行う。モデル・秒数・本数・料金または必要クレジットを確認し、不足している費用承認があれば**実行前**に確認する。ユーザーが許可した範囲は再確認で止めない。
- 無料または低費用の条件がある場合は、それを守る。同じモデルの素材シリーズなど、ライセンス上この文脈に使えるストック映像も候補になる。商用利用・人物の扱い・センシティブな文脈・必要な表示の条件を確認し、架空の症状をストック出演者の実際の病歴として示さない。条件に合う素材が見つかったと装わない。
- 人物を新規生成する場合、必要な基準画像の生成も費用と範囲へ含める。見本の実在患者の顔を複製したり、提供された施術者の顔を患者へ変えたりしない。
- 案件ごとに、人物ID・基準素材・特徴・衣装・使用カット・生成ジョブ／ストックID・権利情報・確認状況を記録する。アクセスできる過去の人物記録を見て、次の作品では別の基準人物を選ぶ。他の利用者の全履歴を知っていることや、世界中で重複しないことは保証しない。
- 足りない映像を準備できない場合は、具体的な不足場面を示し、利用できる施術者の手元・実演や構成短縮で対応する。有料生成を勝手に実行せず、患者動画を必須条件へ戻して終えない。

完成承認版は左下のAI生成ラベルとサンプル表示を入れず、`sceneLabel`・`sampleLabel` を空にする。架空の患者役という前提は台本・制作記録で区別し、実際の来院患者の記録・証言として扱わない。今回の素材ライセンスや利用者の表示指定があればそれに合わせる。架空の感情ストーリーは[承認版](a07-approved-profile.md)の流れを使い、実患者の結果の証拠とは区別する。

### 実際の施術映像と組み合わせるとき

利用者の施術者・院内映像は本人・その院の映像として保持する。別の人へ顔を差し替えたり、架空の患者を施術した記録を作ったりしない。実患者の素材がないときは、実際の施術者の手元・説明・デモンストレーションなど、確認できる素材で手順を説明できる。生成する施術風景が必要なら、架空の説明場面として明示し、その実在施術者・その院で行われた診療記録と誤認させない。

実在患者が映る素材では [face-mosaic.md](face-mosaic.md) を使う。完全に架空の生成人物にはプライバシー目的のモザイクを一律に掛ける必要はない。顔を隠す必要と、イメージ映像であることの表示は別の処理である。混在する場合は実人物・鏡・反射を含む対象範囲を確認する。

## 原見本の構成と文字（観測記録）

数値と原文は [a07.json](a07.json) に保存している。 原見本frame992からの施術1は、初期記録の「側臥位」を実フレーム確認に基づき「うつ伏せで片膝を曲げる動作」へ訂正した。開始・終了時刻は保持している。原見本は1080×1920・30fps、約61.37秒。隣接フレームで確認した22の映像区間がある。時刻は「6:00、6:20、7:20、9:00、11:00、17:00、22:00」から翌朝と来院へ続く。参考は約1.5〜6秒の区間をつなぎ、短い文を複数の場面で順に見せている。新作の総尺・区間数・各区間の秒数を固定しない。

| 役割 | 見本の流れ | 今回の素材の基本担当 |
|---|---|---|
| 導入・日常の悩み | 起床・料理・洗濯・掃除・買い物・夕食 | こちらで同じ患者役のイメージ映像を準備 |
| 院を知る | 夜にスマートフォンでSNSを見る・予約を考える | 患者役＋今回の確認済み院情報。別院の投稿は流用しない |
| 来院・相談 | 移動・迎え入れ・相談 | 移動は患者役、院内と施術者は利用者素材 |
| 施術の説明 | 施術者と動作を見せる | 利用者の手元・実演・使用許可のある実映像を優先 |
| 日常・やりたいこと | 家事・外出・旅行などの希望 | 同じ患者役。改善結果の証明にしない |
| 最後の院情報 | 短い締め＋オレンジ帯の院案内 | 現在のLP／確認済み情報 |

「当たり前のように腰が痛い」「あれ？！全然違う！」「なんだか身体が軽い」等は**原見本の画面文の観測記録**であり、新しい患者の事実ではない。原見本の全部を単純に店名だけ替えて使わない。LPに施術の説明があっても、その架空人物が改善した事実や本人の感想は確認できない。新しい制作では[完成承認版](a07-approved-profile.md)の「帰宅・いつもの家事→腰が軽い／家事が楽という感情→旅行への意欲→来てよかった」という架空ストーリーを先に台本で確認する。本人の実際の結果として未確認のまま転用せず、承認済みの感情の流れを相談案内だけへ置き換えて消さない。原見本の一人称文と本人の実際の発話も区別する。

時刻はVlogの物語上の表示であり、営業時間や予約時刻の事実と混同しない。翌日に変わる場合は流れが読めるようにする。院名・アクセス・施術者の性別や担当・専門表記・最後の案内は今回の確認情報だけを使う。

## 原見本の音声解析と登録時の確認範囲

登録時の音声解析は、VADを使う2つのASRで発話区間0件だった。VADなしで得られた動画尺を超える定型文は採用していない。これは直接試聴ではなく、無音や声が一切ないことの保証でもない。登録当時は曲名・BGM／効果音の内訳・新作へ流用する権利が未確認だった。その後の承認制作では、利用者が許可した見本原音のBGM・アラーム等を使い、静かめの音量と同期を調整した。今後は[承認版の音声方針](a07-approved-profile.md#bgmと効果音)を使い、その制作で利用できる音源を優先する。曲名の同定・第三者再配布許可とは別であり、新規有料生成は暗黙に追加しない。

見本の全体を1秒ごとの61枚、映像切替の隣接72フレーム、導入の文字出現、原寸の代表画像で確認した。動画全編のデコードと、Web用540×960プレビューのデコードを確認。Web用映像は縮小・再圧縮している。AACの2644パケットの中身と表示時刻は原音と一致し、末尾パケットのコンテナ上の長さだけ約0.000658秒差がある。原本保存用の再格納動画は1841映像パケットが元動画と一致する。

0.9.0で行ったのは見本分析と編集パターンの登録で、当時は患者動画生成・新素材の編集・MP4が未検証だった。0.10.5では1制作の患者役生成、ネイティブ合成、文字と行間の表示、編集可能な保存、ローカルMP4と全編デコード、最終文字修正で音声が不変である数値照合を確認し、2026-11-10に利用者が完成承認した。本文書体は承認済み近似で、元フォントの同定ではない。直接試聴・音声込み全編連続再生・別作業者の導入から保存までの実行は未確認。[承認版の制作基準](a07-approved-profile.md)と `a07.json.productionDefaults.validation` を参照する。
