主見本は「整体サロン マサラグレース.mov」。補助の「大島先生１.mov」は人物・発話・施術の参考であり、主見本の文字設計を上書きしない。依頼者が毎回見本を再添付する必要はない。

[a01.json](a01.json)には、元の13カット・23表示区間の構成、画面上で測定した配置、照合済みのCapCut元データを保存している。参考尺は30fpsの1585f（52.83秒）、キャンバスは1440×3114。**参考尺は完成尺の指定ではない。** 40秒・50秒など、台本の読み時間、本人の発話、自然な施術場面の長さから今回の尺を決める。映像の再生速度を変えて53秒へ押し込まない。比率を指定されていなければ元の縦比率を維持し、9:16へ自動変更しない。

## 元データと描画値の区別

2026-10-05、アップロード動画と尺・文章・カットが一致するCapCut原稿と、フォントのname tableを照合した。

- 本文の実フォント：**VDL Ｖ７明朝 U / VDL-V7Mincho-Ultra**。CapCut上の表示名は「明朝」。Noto Serifではない。
- 冒頭の実フォント：**ふい字P / HuiFontP**、元ファイルはHuiFontP29.ttf。
- 本文の原稿設定：白、通常size 20〜22、字間0、主に行間0.27、全周の黒い影1層（alphaおよそ0.64、distance 0、diffuseおよそ0.025）。`styles`に有効な白縁取りはない。
- 冒頭size28・bold=true。原稿の冒頭アニメーションは「カーブスライド」、強調は「スライドアップ」、担当者部分は「スライド（右）」。

これらはCapCut固有の単位であり、CSSのpx・blur値へそのまま代入しない。各cueの`originalCapCut`が原稿設定、`metrics`が輸出動画上の可視字形を測った目標。本文中心Yはおよそ1557だが、対象者は1420、担当者は1244。0.4.4では元フォントによる1案件のChatCut合成を比較・調整し、本文のサイズ換算とSVG黒影の制作値を保存した。旧仮値と元データは`a01-reference.json`に保持する。`renderCalibrationPending=false`はその1案件の較正済み範囲を指し、新しい文字・素材の合成確認を省略できる意味ではない。

旧0.2のNoto・白stroke2.5・二重影は`legacyApproximation`へ退避した。これを元のデザインや同じフォントだと説明しない。元フォントの取得・利用条件は[fonts.md](fonts.md)へ。元フォントが使えないときは、映像構成と台本を進め、字体の高再現が未準備であることを明記する。Notoでの代替はユーザーが承諾した場合だけ行う。

## 映像の選択と尺

カット順はJSONの`cuts`の役割を基本にする。寄り→手元→短い店舗紹介→検査→複数の施術→担当者・相談→案内という流れを守る。各場面の長さとテロップ数は内容に合わせる。原則は直切り。元動画の外観への短いズームぼかし、内観への約0.5秒フェードは再現候補だが、使える素材とツールで自然に成立する場合に用いる。

使用候補ごとに、開始・中間・終盤の画面と区間全体の動きを実際に確認し、施術者の存在、施術が行われているか、手が画面外へ出ないかを記録する。ファイル名や最初のサムネイルだけで採用しない。選択区間の中に、カメラを置いている時間、無人のベッド、床・壁だけの時間を混ぜない。

外観・内観は店舗紹介の目的がある場合だけ短く使う。新しい案件の既定目安は各2秒以内、連続4秒以内。これは見本の実測（各約3.1秒）とは別の、無人映像が長く続かないための選択目安であり、明確な意図があれば案件で調整し理由を残す。施術者と実際の施術が見える映像の両方を必ず含める。足りない場面は別角度の適切な施術カットへ置き換えるか、その役割を省いて短くする。旧店舗映像を新店舗の映像として挿入しない。

初回案内のcontain・上下黒帯などは元構成に合わせるが、重要な施術の手元を切らない。顔ぼかしが必要な素材は、その区間の動きに合わせて調整する。明るさは微調整のみ。肌や白い壁の白飛びがないか変更前後で比べ、色味や演出を大きく変えない。

## 二つの編集方法

- `reference`：LPの確認済み事実から文章を作り、元の役割に割り当てる。素材音声は既定ミュート。長い店名等はユーザー指定の表示名を優先し、支店名を自動追加しない。未指定の固有名詞は保ち、文の分割・自然な改行・使用区間の延長で調整する。読む時間が不足すればコピーを短くするか尺を延ばす。見本の未確認の資格・効果・保証・予約混雑を流用しない。
- `verbatim_speech`：本人の元声を保持し、聞き取りを確認した文章を要約・言い換えせず表示する。[フィラー・長い間の整理](speech-cleanup.md)を先に実行し、意味のない発声と不要な間をカットする。意味のある返答・息継ぎは残し、文の言い直しの削除は依頼がある場合に限る。その後、採用した単語を元音声時刻から完成タイムラインへ写す。文や単語の途中の切断を避け、誤認識のみ修正する。話す順序を優先し、意味が変わる並べ替えはしない。元の話し方のまま字幕表示尺を決め、参考動画の23枠へ無理に収めない。

新しいAI音声・BGMはどちらも既定で追加しない。「AI音声なし」を本人の声までミュートする意味にしない。

## 配置の計算と適用

[planning.md](planning.md)の形式で案件の入力を作り、`scripts/timeline_plan.py`を実行する。使用した素材区間から今回のカットと総尺を計算し、referenceでは役割内の相対タイミングを保持してテロップを写す。speechでは元音声に合わせる。原稿の開始フレームと、入口アニメーション後に文字が見えるフレームは区別する。

出力を現在のChatCutツールで適用する。映像・文字・装飾を独立した編集可能項目にし、既存の見本を直接変更しない。実際のアセットID、素材尺、LPの出典は今回取得したものだけを使う。

文字は各行の送り幅で中央揃えし、可視字形の範囲を目標centerYに合わせる。行ピッチと改行は見本に近づけ、固有名詞を途中で不自然に切らない。長い文章を極端に小さくする前に、文を分割して尺を見直す。SVG字形の場合はunitsPerEmから実寸へ換算する。幅や高さだけを後から変形して文字を横長にしない。

`main_black_band`のみ黒帯をx12/y1302/幅1416/高さ510、不透明度0.53で文字の後ろへ置く。バッジ、証拠写真、注記、強調の区間は今回の尺へ写し、確認できる内容がある場合だけ有効化する。helperは誤った旧店舗の装飾が自動表示されないよう初期値を無効にする。資格がないのに資格バッジを埋めたり、保証がないのに注記を出したりしない。

## 修正と完成確認

### 参考動画と合成画面を比較して仕上げる標準手順

0.4.3以降は、A01も参考動画へできるだけ忠実に寄せることを制作の標準とする。数値を配置して終わらず、今回の素材・文字を使ったChatCutの実際の合成画面と主見本を並べて比較し、差のある箇所を調整して再確認する。A02で行った比較・調整の進め方を引き継ぎ、字体や位置の数値自体はA01の見本を基準にする。

1. 主見本の各場面に対し、今回の字幕と映像の対応を決める。支給ナレーションがあるときは発話時刻を保ち、同じ役割の見本場面と比較する。
2. 全テロップの静止後の画面で、元フォント、可視字形の大きさ・太さ、位置、改行、行間、白い塗り、黒い影と背景の境界を確認する。見本の原稿数値と実際の見え方が違えば、可視字形を基準に較正する。
3. 入口・移動途中・静止後の画面と連続した動きで、カーブスライド、スライドアップ、右スライドの方向・速さ・表示タイミングと、カットのテンポを比較する。文字・影の途中切れも確認する。
4. 目立つ差のある箇所を修正し、その箇所と前後を再確認する。店名・地域・数字など今回の文字でも読みやすさを確かめ、最後に全編を連続再生する。見本、比較時刻、修正点、再確認結果、残る差を案件メモに記録する。

見本映像を開けない場合は、同梱仕様で進められる作業を進めながら、その映像比較に必要な入力・アクセスを確認する。比較できたようには報告しない。必要な元フォントがなければ不足を知らせ、黙って代替しない。0.4.3の手順更新と0.4.4の1案件の実制作確認を区別する。今回の案件で実施していない全編再生・音声検証・書き出しを、承認だけで実施済みにしない。

文字修正は[planning.md](planning.md)の`text_revision.py`で、対象cueの開始・終了と映像・音声を保ったまま新しい字形と幅を準備する。文字を直すと字幕が変わる経路と、単語を削除すると映像・音声も切れるTranscript編集を混同しない。字形埋め込みの場合、ChatCut上でpropsだけを変えて未知字を追加すると字体が変わる実装は不可。Codex経由の修正で字形を再生成してから反映する。ChatCutでの直接入力が字形を自動補完しない場合、その制約を利用者へ明記する。

全テロップ区間、長い院名・地域名、特殊文字、数字、入口と最後の文字、影と背景の境界を実際の合成画面で比較する。変更後の各カット境界±2f、字幕の開始/中間/終了直前を今回のplanから算出して確認し、旧1585fの固定確認リストを使わない。最終的には連続再生して、無人映像の混入、発話と字幕、読み時間、明るさを確認する。ツール成功やplanner合格だけで完成扱いにしない。

JSONの検証フラグは過去の検証範囲であり、新しい案件の成功を意味しない。元フォントの合成表示は0.4.4の1案件で確認済み。発話モードの一連の制作、全編連続再生とDesktopローカルMP4、別アカウントでの試験は未完了。
