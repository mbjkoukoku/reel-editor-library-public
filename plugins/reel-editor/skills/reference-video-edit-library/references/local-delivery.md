# 費用を抑えたMP4保存

確認日：2026-10-15。利用者の最新の指示を優先する。

## 編集と保存の経路

CodexからChatCutを編集するとき、標準では素材のカット・配置・テロップ・装飾を作り、提供素材を使う。編集用のMotion GraphicコードはCodexが作成して現在のツールへ直接渡す。ChatCut内蔵Agentに依頼を送り直したり、ChatCutの映像・画像・音声・音楽・効果音・シェーダー等の有料生成を暗黙に呼んだりしない。

標準の納品先はChatCut Desktopのローカル動画書き出し。ホスト型プラグインかDesktop接続かという名前だけで、ローカル・クラウドを断定しない。現在のツール定義に明示された保存モードと実行結果を確認する。`local`が利用できる場合はそれを選び、対応するエディタを開いた状態で進める。ローカル機能が明記されていなければ、クラウドのレンダリング操作で代用しない。

ローカル保存が使える場合は、対象プロジェクト、タイムライン、範囲、解像度、フレームレート、形式を確認し、その環境のツール・スキルに沿って保存する。返された処理IDと完了結果を記録する。ダウンロードURLを返さずブラウザ等からローカル保存される経路では、実際に保存されたファイルを確認する。接続方式を推測してツール名や保存引数を作らない。

ローカル保存を直接操作できない場合は、利用者がDesktopで最後の操作をする。次を一度に渡す。

1. 今回のプロジェクト名・タイムライン名と、ツールが返した編集画面へのリンク。
2. 同じChatCutアカウントでDesktopを開き、そのプロジェクトとタイムラインを選ぶ案内。
3. 素材が表示され、最新版の文字が反映されていることの確認。素材が欠ける場合は利用者の正しい素材へ再リンクし、別店舗素材で埋めない。
4. DesktopのExport → VideoでH.264/MP4を選び、解像度・フレームレート・書き出し範囲と保存フォルダを指定する手順。元の縦横比は変えない。A01は30fpsで、必要がなければ1080pを初回確認用に使える。
5. Desktopを開いたまま処理し、完了後Show in FinderまたはOpenでファイルを開く案内。

編集タイムラインだけ完成した場合は「編集完了・MP4保存待ち」と伝える。ローカルファイルを確認していないのに「保存済み」と言わない。ファイルが得られたら尺・解像度・フレームレート、最初・最後・修正箇所・テロップ・音声の有無を確認する。修正版は古い書き出しと区別できる名前で保存し、今回の変更が映像に反映されているか確認する。素材の保持と部分修正は[media-revisions.md](media-revisions.md)に従い、元素材を保存完了前に移動・削除しない。

納品版はファイル名・サイズ・ハッシュなどで案件内の検証記録と対応させる。保存値の読み戻し、全ストリームのデコード、合成画像、顔モザイク、音声の数値検査、直接試聴、音声込みの全編再生、ユーザーの完成承認を別々に記録し、未実施項目を残す。デコード成功や完成承認を実聴の代わりにせず、新版の比較なしに旧版の結果を新しい出力へ引き継がない。不変の映像・モザイクを再利用する音声修正は[全フレーム比較の条件](provided-narration.md#修正版の確認と保存)に従う。AACなどのデコード末尾に余白サンプルがある場合は、有効なタイムライン尺・ストリーム尺と分けて調べ、余白だけを根拠に音声の欠落や尺ずれと判断しない。

## 費用と検証

確認時点の公式クレジット方針では、通常のタイムライン編集、アップロード、文字起こし、書き出しはChatCutクレジットを消費せず、ホスト型の生成処理がクレジット対象となる。Codexの利用枠、ChatCutの生成クレジット、プランや経路による書き出し制限は別であり、全工程を無条件に無料とは説明しない。固定の無料分数を前提にせず、実行時のツール結果と現在の公式条件を確認する。クラウド書き出しにクレジット消費がない場合でも、それだけでローカル保存指定を変更しない。

2026-10-14の1制作事例では、ホスト型ツールが`local`・`browser`を返した経路でMP4の実ファイルと修正箇所を確認した。これはその環境での実測であり、すべての接続・アカウントで同じ経路が使えるという保証ではない。公式のWeb・Desktop書き出し案内と、個別ツールで確認した経路を区別する。音声込みの全編連続再生はこの事例では未検証であり、保存済みという結果だけで全編再生も確認済みとは扱わない。

まず一人の利用者が自分の環境で、プラグイン導入、素材＋LPからの編集、DesktopでのMP4保存、保存した動画の再生まで試す。料金表示だけで「追加費用なしで全工程が完了した」と判断せず、必要なら本人のクレジット履歴も確認する。この共通版での別アカウントの一連の実地試験はまだ未実施。
