# A02承認版の描画・読みやすさ

`a02.json`の適用値から今回の文言用のMotion Graphicを作る。これは描画仕様であり、店舗素材・過去の本文・フォント本体・JSXファイルを同梱するものではない。ChatCutの現在のホストに対応するスキルに従い、コードを直接渡す経路かソースファイルを取り込む経路を使い分ける。

## 字形と配置

1. 各cueの`postscriptName`でフォント実名を照合し、今回の全文字の輪郭とadvanceを取得する。元見本の同定状態と承認版の採用字体を区別する。
2. 文字サイズに各語の倍率を掛け、実advanceで行幅を計算する。幅上限は960px。位置は静止後の実字面中心をX540/Y1140へ置く。文字を省略したり、文字数だけで幅を推定したりしない。
3. 2行を超える文は発話・意味の境界でcueを分ける。通常の行送りは1.15em。大小混在の判定はスタイル名だけでなく、実際に適用する語・文字ごとの倍率で行う。混在する場合は、幅調整後の文字サイズと各倍率を掛けた字形の上下限から行のベースラインを決め、実上下限の間に基準文字サイズの0.12emの空白を取る。大小混在にも固定1.15emを流用しない。空白文字の送りも保持する。
4. フォント座標のパスを`scale(s,-s)`で描く場合、縦グラデーションが上下反転する点に注意する。JSONの`fillGradientStops`は画面上端→下端の順。SVGのy1/y2を反転するか画面座標で設定し、赤上部→オレンジ下部などを実フレームで確認する。

幅調整後の基準文字サイズ、各行の実字面の上下限とベースライン、実測行間、最大行幅、静止後の全体中心を案件メモへ残す。字形だけの数値検証と、縁・影・斜体・動作を含む合成画面での読みやすさは別々に確認する。

## 縁と色

`strokeLayers`は外側から内側への描画順。各層を重ねた後に文字の塗りを描く。`widthPx`はSVG strokeの全幅で、輪郭の外へ出る量はおおむね半分。黄色強調は赤17px→黒9px→黄塗りの順。金色明朝は白16px→暗色11px→黄塗りの順。`emboldenPx`は塗りと同色の追加stroke。

見本に寄せるだけでなく、実際の肌、ベッド、床、壁、暗い服の上で読めることを優先する。金色明朝の旧い淡色縁や白い影は使用しない。`fill`/`outlineColor`/`shadowColor`の編集プロパティとコード既定値を同時に更新し、古いpropsが新色を上書きしないことを確認する。アプリ全体のテーマカラーを全テロップへ流し込まない。

## 入場と自然寸法

`animations`または計画の`appliedAnimations`はcue開始からのフレーム。タイムライン開始時刻を二重加算しない。原見本の`originalCapCut`を優先して承認版の動きを戻さない。

- 急ズームは3.5→2→1.08→1.02→1倍（0/2/5/7/15fr）。残像は右17px・下12px・ぼかし2pxで薄く収束する。
- 金色明朝は右260→75→0px（0/4/9fr）。白発光は最大0.28、7frで消す。白レイヤーを文字と暗い縁の背面へ描き、文字色を隠さない。
- ほかの指定された強調はJSONの発光を使い、読みにくければ同じ背面・弱い発光の方針で調整する。全字幕へ発光を追加しない。
- クロマズームは指定の赤・シアンの背面シルエットを分離し、9frで通常サイズ、15frで色ずれを解消する。

自然寸法は、全期間の字形・太縁・影・白発光・色ずれを含む形へskew/scale/translationを適用した境界の和集合から決める。静止時の小さい枠で拡大中の文字をクリップしない。内側は元寸法のまま固定し、内側の中心を変形の原点とする。外枠の左上を補償し、静止後の字面中心X540/Y1140を保つ。今回の案件で使った巨大な幅の数値を他の文言へ固定しない。

現在のネイティブ合成で、自然寸法を正しく設定してもプレビューサイズに応じた欠け・不正な拡縮が再現する場合だけ、現在の出力幅・高さを明示したviewport wrapperを代替候補にする。内側の字形・変形原点・動作・静止後の位置を保ち、そのホストで取り込み・配置できることを確認する。複数のプレビューサイズと実際の書き出しで、入場中から静止後まで再確認する。通常の自然寸法を一律に置き換えず、他案件の表示枠や補正値を固定で流用しない。

## 合成確認

文字が停止したフレームだけでなく、入場直後・途中・停止後・最終表示をまとめて確認する。画面端を越える意図したズームと、資産内の四角い枠で切れる描画不具合は区別する。長い地名・店名・数字・疑問符も実際の全文で確認する。短い表示区間ではアニメーションを短縮し、読む時間を残す。ツール成功やJSON検証だけで見た目の確認済みとしない。

## 写真を横へ動かす場面

アクセスなど、実際の場所を示す短い写真区間に適用する。文字は従来の独立レイヤーに保ち、写真の動きで文字まで移動させない。

- 写真の実寸から縦画面を覆う倍率と移動余白を計算する。横移動の開始・中間・終端で空白や元画像の黒い縁を出さず、入口・看板など説明に必要な部分を残す。余白が足りなければ移動量を減らす。元解像度と拡大後の粗さを確認し、不要な追加ズームを避ける。余白を減らす指定がある場合は、次項の基準で構図と画質の釣り合いを判断する。
- 余白を減らす指定では必要な部分を残して拡大し、全面表示で入口・看板などが切れる場合は最小限の背景を残す。全写真を一律の倍率にせず、[共通の写真拡大基準](media-revisions.md#説明に合う写真と控えめな動き)と拡大後の顔の確認に従う。
- 現在の編集ツールで移動を表現できる方法を使う。手書きMotion Graphicが必要な場合は、取り込んだ写真を編集可能なimageプロパティへ結び、写真・構図・移動量を後から変更できるようにする。有料動画生成を写真のパンのために呼ばない。
- 写真だけを差し替える依頼では、元の音声・字幕・開始終了時刻を保つ。新しい写真の縦横比に合わせ、クロップと移動量を再調整する。別写真へ古い寸法をそのまま適用しない。
- 実際の字幕を重ね、入場中・静止後・写真区間の終端と前後のカットを確認する。書き出した場合はMP4でも差し替えが反映されているか確認する。

0.6.1の実制作では、支給外観写真への差し替え、水平移動、字幕と前後カットの合成表示、local経路で保存したMP4の修正箇所を確認した。個別の写真、移動量、尺をA02全体の固定値にしない。全編の音声込み再生や、全環境での再現を検証済みとはしない。
