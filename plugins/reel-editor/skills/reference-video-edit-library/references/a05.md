# A05：施術前・施術後のビフォーアフター

見本は「0711.mov」。同じ患者さんの施術前と施術後を、動きと常時表示のラベルで比較するパターン。院名と配色は今回のLPから取り、患者さんの顔には動きを追うモザイクをかける。見本の院名・緑色・結果を表す言葉・47.8秒という長さを、他院へ固定で流用しない。

## LPから短い画面文を確認して、素材を受け取る

1. **最初は依頼文と今回のLPだけで、画面に載せる短いテロップ案を作る。** 正式な院名、LPの主色・アクセント色、見出し「施術前」「施術後」を示す。長い読み上げ台本やAI音声は作らず、まだ動画編集は始めない。LPは基本情報と配色の出典であり、今回の患者さんの結果を証明するものとして扱わない。
2. 案を確認してもらったら、**「施術前・施術後が分かる素材動画を入れてください」**と案内する。ファイル名・番号・時刻で対応が分かるとよい。素材を受け取る前に、今回の歩き方や症状の変化を推測して文章にしない。すでにユーザーが具体案を承認している場合は、その承認を引き継ぐ。
3. 素材を確認し、前後の対応と比較する動作を確定する。ファイル名の意味、明示された番号、映像内ラベル、撮影メモなどを使う。動きが悪そうだから施術前、という判断はしない。対応が不明な箇所だけを確認し、それ以外の素材整理は進める。
4. 承認済みの短い画面文に合わせて、見本と同じ**施術前→施術後の順番**を基本に編集する。顔モザイク、院名帯、前後ラベル、必要な短い補足を加える。現在の接続に対応したChatCut基本・編集・検証スキルを使い、実際に利用できる機能で実装する。
5. 文字、前後の切り替え、動作の見え方、顔隠しを確認する。完成した動画全体を確認し、書き出しまで依頼されたら[ローカル保存](local-delivery.md)へ進む。

`executionRoute: before_after_comparison`はライブラリ内の分岐名で、ChatCut API名ではない。A01〜A03用の固定カットhelperやA04の発話整理経路へ無条件に流さない。`timeline_plan.py`・`text_revision.py`の対象ではなく、今回の素材・前後の対応・顔追従・LP配色に応じて編集する。

## 比較が伝わるカットと表示

同じ動作の始まりから終わりまでが分かる区間を選ぶ。歩行なら足元と体の動き、検査なら検査対象の動きを残し、字幕や過大なトリミングで隠さない。不要な準備や重複部分は詰めてよいが、無言で歩いている・検査している時間を「間」として機械的に削らない。

速度は原則そのままにし、施術後だけ速くしたり、前後で異なる切り取り・反転・明るさによって変化を演出したりしない。見本は並列画面ではなく、前後を順に見せる構成。並列表示は今回の素材が同じ動作を比較でき、確認済みの案に合う場合だけ使う。見本の24.3秒で必ず切り替える、47.8秒に必ず収める、といった固定はしない。

院名帯を上部に置き、その下に「施術前」「施術後」を同じ位置・大きさで常時表示する。ラベルの切り替えは実際の映像切り替えと同じフレームに揃える。見本にはラベルが1フレーム先に「施術後」へ変わる箇所があり、そのずれは再現しない。

## 院名・配色・文字

[a05.json](a05.json)の`renderTargets`と元見本を比較する。上部は角丸の院名帯と白文字。その下の前後ラベルはヒラギノ角ゴシックW6・太字、黒文字と白縁。補足を入れる場合は同じW6の太字・白縁を基本に、LP由来の読みやすいアクセント色を使う。見本では右下に3行だが、今回の文と足元の位置に合わせて調整する。

院名帯の元フォント指定はCapCut内の`SystemFont/en.ttf`で、日本語の実際のフォールバック字形は未同定。W6もTTC内face番号は元データに指定がない。フォントファイル名と完全な描画一致を分け、別の環境では利用可能なフォントと字幅を確認する。フォント本体は配布しない。

見本の帯色`#0c7217`、補足色`#065e0f`は分析値。新しい院ではLPの配色に置き換える。LPの色が薄い場合は濃淡と文字色で読みやすさを保つ。患者さんの肌や映像全体へブランド色をかけない。明るさ調整は必要な範囲で前後を揃える程度にとどめる。

見本の補足「痛みなく／スタスタ／楽に歩ける！」は、今回の患者さんの発言・確認済み事実があるときだけ内容を作り直す。LPに載っている一般的な訴求だけでは採用しない。確認できなければ前後ラベルのみ、または中立的な補足とする。見本では文字の入場・退場アニメーションは設定されていないので、派手な効果を自動追加しない。

CapCut固有の文字サイズ・座標・縁幅をCSSのpx値として直に使わない。720×1280の書き出しでは帯はおよそx32〜689、y29〜172。文字や余白は院名の長さに合わせて実際の合成画面で較正する。無効なトップレベル影設定を、存在する影として追加しない。

## 顔のモザイク

[顔モザイクの共通手順](face-mosaic.md)で範囲・追従・座標・境界と書き出し後の確認を行う。比較動作を妨げないよう顔だけに必要な余白を取る。

**今回の依頼はモザイク。見本に既に入っている処理は円形マスクのぼかしであり、同じ種類ではない。** 新しい素材には顔を追うピクセル状のモザイクを施す。見本のマスク位置やキーフレームを別の患者さんへ流用しない。

正面だけでなく横顔、振り向き、画面への出入り、鏡に映る患者さんの顔も対象にする。直接の顔と反射は必要に応じて別領域で追い、目・鼻・口・顔の輪郭が分からない強度と余白を取る。院名帯やテロップで偶然隠れている状態だけで完了にしない。体や足元の比較をなるべく妨げず、動きに追従させる。

全区間を完成解像度で再生し、カット、顔の出入り、向きの変化、遮蔽、追跡・キーフレームの切り替えでは前後のフレームも確認する。短時間の見落としや追従外れがあれば範囲やキーを修正して確認し直す。未確認の区間があれば「顔隠し確認済み」と言わない。

現在のツールに必要なマスク機能がなければ、まず現在のホストの編集規約と利用可能な機能を確認する。外部処理で派生素材を作る方法は、そのホストが許可し、依頼範囲に合う場合に限る。許可されていないローカル焼き込みへ切り替えない。対応可能な場合も原本を保持し、マスクと時刻の記録を残し、院名や前後ラベルはChatCut側で編集可能にする。確実に隠せない場合は該当区間を伝え、顔が見えた完成品として渡さない。存在しない追跡APIを仮定しない。

## 音声と修正

指定がなければ今回の素材の元音声を維持し、AI音声・BGM・効果音を暗黙に加えない。元音の扱いをユーザーが指定したら優先する。A04と違い、発話の全文テロップや自動フィラーカットをこのパターンの必須工程にしない。発話カットを追加依頼された場合も、比較に必要な連続動作を守る。

文字を直す場合は該当する独立テキスト・図形・MGを更新し、承認済みの映像、モザイク、区間時刻を保つ。字形パスを使う場合は文字欄の変更だけでは反映できず、Codexによる字形と配置の再生成が必要なことがある。

## 分析と検証の範囲

見本は47.8秒・720×1280・30fps・1434フレーム。対応するCapCut草稿は1080×1920。院名帯は全編、前ラベルは0〜24.2667秒、後ラベルは24.2667〜47.8秒、補足は31.3333秒から末尾。映像の前後切り替えは24.3秒。4、8、21、24.3、28.8、37.3秒の画替わりを境界フレームで確認した。素材本体は既にカット済みの一本であり、元撮影素材の全カット意図までは確定していない。

0.5秒間隔の96フレームと代表的な切り替えを確認し、患者さんの顔付近の既存ぼかしを観察した。**全1434フレームの顔隠し安全性を認定したわけではない。** 見本の音声試聴も未実施。音声トラックはあるが、草稿に別BGMトラックがないという理由だけで「BGMなし」と断定しない。

今回の登録は見本分析と手順の追加。新素材でのChatCut編集、顔モザイクの全編追従、別院LP色の合成、音声試聴、完成MP4の検証は未実施。実際に行った確認と未確認を分けて伝える。
