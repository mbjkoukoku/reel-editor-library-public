# フィラーと長い間を整理してからテロップを作る

A03や「音声なし・テロップだけ」の指定では、この音声整理を実行しない。施術映像のカットは見える動作・場面・読む時間で判断する。

0.4.9以降のA01・A02、および0.6.0で追加したA04の標準手順。本人の声をテロップ化する編集と、支給ナレーションを使う編集で適用する。素材と音声を受領して編集する段階で実行し、「まず台本だけ」の段階、誤字・表記だけの修正、音声を使わない映像には適用しない。「カットせず字幕だけ」「フィラーも残す」など今回の明示指示を優先する。通常の整理は追加指示・再承認を求めず進める。

## 残すものとカットするもの

- 原音と前後の文脈で、意味のない「えー」「あー」「えっと」「うーん」などを削除対象にする。同じ表記でも、迷い・同意・返答・感情を伝える発声は残す。文字列の一致だけで一括削除しない。
- 0.8秒以上の間を確認候補にし、不要な部分だけ0.25秒程度を出発点に短縮する。冒頭・末尾の不要な録画待ちも確認する。自然な息継ぎ、文の区切り、強調や返答に必要な間、施術・検査・実演の動作を見せるための時間は残す。数値は全箇所への強制上限ではなく、話し方に合わせる目安。
- 意味のある言葉・承認済み台本の内容・発話順・再生速度は保つ。聞き取れない発声は推測して削除しない。明らかな言い直し・言い間違い・同じ内容の再試行を整理する指定がある場合は、完成した自然な1回を残し、失敗した断片や重複部分だけを削る。意図的な反復・強調や、後の文にない主語・前置き・条件まで重複と決めつけない。
- 採用区間の端はASRの単語境界だけで機械的に詰めない。語頭・語尾の音、助動詞・終助詞、文末の「です／ます／ですね」などが自然な言い切りに必要なら、そのまとまりまで残す。固有名詞・専門語・複合語を途中で切らず、次の言葉と音が重なる場合は小さく残すか、より自然な別テイクを選ぶ。
- テロップの文字だけを消して済ませず、対象の再生区間をカットする。話者映像と元声を一緒に使う場合は両方を詰める。別の施術映像を重ねる場合は音声側を整理し、その完成時刻へ映像を合わせる。

ASRに不自然な語・重複・極端に短い単語区間があっても、それだけで原音の言い間違いや削除対象と判断しない。原音を確認できない箇所は音声を保持し、不確実な元時刻と未確認の理由を残す。字幕へ承認済み表記を使う判断は原音の発話確認と分け、単語境界が信頼できない場合は確認可能な句単位の時刻へまとめる。文字数から時刻を作ったり、表記の承認を根拠に音声を削ったりしない。

BGM入りの素材で声の一部だけを直す明示指定は[BGMを保って声の一部だけを修正する手順](audio-partial-repair.md)を優先する。一般のScript単語削除で指定外の音やBGMまで切らず、この依頼を全編のフィラー整理へ広げない。

## 言い直しと重複の判断

1. 前後の行をつなげて一文・一つの説明として読み、同じ意図を言い直した再試行か、意味のある反復かを判断する。
2. 残す候補は、主語・目的語・条件・結論まで含む完成した発話を優先する。後のテイクが完全とは限らないため、「後を残す」を機械的な規則にしない。
3. 失敗した語、途中で止めた断片、完成版に完全に含まれる余分な再試行だけを削る。別々の未完成な断片をつないで、話していない一文を作らない。
4. 同じ語がカット境界の前後に残っていないか確認する。重複を取るために前の文の自然な語尾まで削らず、文末と次の文の始まりを別々に評価する。

## ChatCutで実行する

現在の接続に対応するChatCutの基本・発話編集・文字起こしスキルを読み、実際に使えるツール定義に従う。以下はhosted `chatcut` の手順。別のDesktop接続へ同じAPI名を仮定しない。

1. 今回の原音を確認し、文字起こしの誤認識は原音に基づいて修正する。対象の音声トラックを確認し、`read_script`で`showSilence:true`を指定して、実在する単語と間を読む。トラック名を音声だからA1と決めつけない。時刻を文字数から創作しない。
2. 不要な日本語フィラー・間・今回指定された明らかな言い直しをScriptへまとめる。`clean_script`の固定フィラー一覧は日本語を含まないため、それだけで日本語のフィラー除去が完了したと扱わない。意味に依存する削除は、原文を保って対象語を`~~...~~`で囲む。無音短縮は`[silence=1.2s→0.25s]`のように実際の元時間から書き換える。必要な間が混じるトラック全体へ、無条件の一括短縮をかけない。フィラーの両側に残る無音はカット後に合算されるため、つなぎ目の合計で自然な間にする。行末を短くするときは、原音の文末表現と次の行の語頭まで確認し、意味のある語尾を落とさない。
3. `apply_script`で反映する。ファイルが提供される接続ではその編集経路、インラインで返る接続では編集済み`timelineMd`を使い、現行仕様のリビジョン情報を保つ。文字起こし訂正機能でフィラーを消したことにしたり、単語検索と物理split/deleteでScript編集を迂回したりしない。ユーザーがプレビューのみを求めた場合は適用せず、その指定を守る。
4. 反映直後に`read_script`を再実行し、完成側で聞こえる文章を先頭から読み直す。削除対象が残っていないか、同じ語が境界の前後へ二重に残っていないか、固有名詞・専門語・語尾が欠けていないかを確認する。意図した文章と違えば字幕へ進む前にScriptを直す。
5. 構造変更後に現在のChatCut発話編集手順が音声スムージングを提供していれば、全カット確定後に短いクロスフェード／端フェードを一度適用する。これはクリック音を抑える仕上げであり、悪い単語境界や不自然な言い直しを隠す代用にはしない。
6. カット後のタイムラインを基準に字幕を作る。既存のネイティブ字幕が有効なら一連の編集後に一度refreshし、表示文を読み直す。手動修正済み字幕は削除前の語を保持する場合があるため、音声から消したフィラー・言い直しが画面に残っていないかを確認する。A01/A02の独自テロップ・文字アニメーション・別映像、A04の効果音は自動で再同期されるとは限らないため、実際の完成時刻に合わせて配置し直す。別トラックが自動で詰まったと仮定せず、末尾の黒画面や効果音だけの余りも確認する。
7. 元音声の採用範囲と完成時刻、削除した語・間を案件メモへ記録する。変更した各つなぎ目は前後の発話を含めて聴き、語頭・語尾、音の途切れ、詰まり、映像の飛び、字幕ずれを確認する。語句を切った境界は直前・直後だけでなく一文として再生し、必要な語尾や間は元の音声から戻す。最後に全編を確認する。試聴できなければ、構造・合成画面の確認と聴感未確認を分け、問題なしと断定しない。

## 計画helperとの境界

`timeline_plan.py`はフィラー・無音の検出やScript編集を実行しない。カットが必要な発話案件では上記のScript編集を先に行い、最新タイムラインを正とする。カット前の`shots`・`speechSegments`から作った計画を再適用して、消した発話や間を復活させない。既存helperの話者映像の計画は、整理が不要な素材やユーザーがカット不要と指定した案件に限って使える。別ナレーション＋映像は従来どおり[支給音声の手順](provided-narration.md)で組む。

この追加はCodexが実行する標準手順の実装。プロンプト・文書の検証と、実素材のカット・試聴・MP4確認は別であり、その案件で実施した範囲だけを報告する。
