# A01：承認事例から反映する制作手順

この資料は、A01「整体サロン マサラグレース」を主見本とした1件の制作で、利用者の修正と最終承認から得た手順をまとめたもの。次回の初回提出でテロップを含む編集を揃えるために使う。個別店舗の情報や承認済みの広告文を、別店舗の事実として流用しない。

ここでの「初回提出」は編集済み動画の初回提示を指す。「まず台本だけ」の依頼では[台本作成の手順](script-first.md)に従い、LPから台本とテロップ・仮の映像案を提示して止める。素材の提出や字幕の実配置を台本作成の条件にしない。

## 初回提出の基準

- 映像に加え、本文、地域、店名、強調文字、締めまで、予定したテロップを実際にタイムラインへ配置してから完成版として提示する。原稿、下書きマーカー、冒頭文字だけの状態を「テロップ完成」と報告しない。
- 途中経過を見せる場合は、未配置の内容を明記する。素材不足や操作不能で完成できない場合も、何が実行済みかを区別し、完成したように扱わない。
- 書体と利用可能な再現手段を早期に確認する。必要なフォントがない場合は黙って代替せず、文字以外の進められる作業を続けながら不足を知らせる。
- 各予定区間の代表画面、切り替え前後、入口・強調の動きを、実際の合成画面で確認する。意図した無表示やアニメーションの途中を、機械的にテロップ漏れと判断しない。

## 原稿と店舗情報の扱い

- 見本の構成と語り口を基準にし、地域、店名、サービス、実績、条件、予約先など、今回の店舗と合わない事実を差し替える。根拠のない効果、実績、体験談は追加しない。
- LPの正式名称と、動画内で使う表示名称を別に扱う。利用者が短い店名を指定した場合は、その表記を保持する。支店名や地域名を後から自動で戻さない。
- 締めを独自の営業時間・電話番号案内などへ変更する前に、見本の締めを今回の情報で成立させられるか確認する。この事例の承認された締めは、相談の呼び掛けの後に「初回の保証案内 → 試しやすさ → 予約状況への言及 → 確認を促す行動案内」という4区間の構成だった。
- 保証や予約状況は店舗固有の情報である。この構成を使う場合も、内容と条件は今回の資料または利用者の明示指定に基づける。別店舗にも同じ保証や混雑があると推定しない。
- 利用者が今回の文言を明示的に指定した場合は、既にある指示を尊重して反映する。同じ許可を重ねて求めない。明確な矛盾や不足がある場合だけ確認し、黙って別の事実へ書き換えない。
- 支給ナレーションがある場合は、その内容、順番、実際の発話時刻を優先する。見本の固定秒数に合わせて音声を勝手に切る、速くする、重ねることはしない。音声がない場合の編集テンポを、そのまま音声付き案件へ固定適用しない。

## 文字の再現と修正

- 本文の原書体は「VDL Ｖ７明朝 U」（識別名 `VDL-V7Mincho-Ultra`）。この事例では元書体の字形を使用し、白い塗りに白の縁取りを加えず、黒い影を付けた。代替フォントとの同一視や、フォントの使用許諾を別途確認済みであるとの主張はしない。
- 元のフォントファイルを共有資料へ同梱しない。字形を保持する実装を使う場合は、修正後の文字に必要な字形が揃うことを確認する。未収録文字を黙って別書体で表示しない。
- 字形の実際の外接範囲と行幅で中央を合わせる。フォント名とサイズ値だけで位置が一致したとみなさず、改行、行間、文字幅、太さ、影を合成画像で比較する。
- この事例の作業座標は `1440 × 3114`。本文サイズの出発点には元の CapCut サイズ値の `25 / 3` 倍を用いた。影の調整値は SVG の膨張処理 `feMorphology` の半径 `6 px`、`feGaussianBlur` の標準偏差 `8 px`、黒の不透明度 `0.653`。これは同じ見た目を保証する万能値ではなく、当該画面で採用した調整値である。別のキャンバス寸法、レンダラー、背景では、再び見本と並べて調整する。
- 長い店舗名などは、その文字で表示幅と改行を確認する。必要に応じて文字サイズを調整し、見本と同一サイズでなくなった場合も同一と報告しない。
- 文言だけの修正では、書体、影、位置、表示時刻、動きを維持することを基本にする。修正後に文字切れ、字形欠落、極端な縮小、不自然な改行がないか確認する。
- 冒頭の原書体は「ふい字P」（識別名 `HuiFontP`）。この事例では原書体が利用できたが、最終的なタイムラインでは冒頭の文字が削除されていた。この個別状態から、今後のA01でも冒頭を常に削除するという規則を作らない。

## 最終状態とAI音声原稿の同期

- 最終タイムラインの実際の文字と順番を正本にする。修正後に読み直し、テロップ一覧、AI音声用原稿、作業報告を同じ状態へ揃える。ファイル名に「final」が含まれることだけを最終版の根拠にしない。
- 既に編集済みのタイムラインがあり、そこからAI音声用原稿を作る依頼なら、現在のテロップを確認してから抽出する。編集前の「まず台本だけ」ではタイムラインを要求せず、[台本作成の手順](script-first.md)でLPから原稿を作る。読み上げ用の句読点や改行は整えてよいが、削除済みの冒頭、旧地域名、旧店名、変更前の締めを戻さない。強調文字を含め、読み上げる語句の順番と重複を確認する。
- 表示件数は実際の項目から数える。本文とは別の強調文字、重なって表示される文字、削除済み項目を区別する。「全区間配置済み」「空白なし」などの旧報告を無条件に引き継がない。
- AI音声用原稿の作成依頼だけで、新しい音声生成やBGM追加を開始しない。音声が後から支給された場合は、その音声に合わせて映像とテロップを調整する。

## この事例で確認できた範囲

利用者は、文言修正とAI音声用原稿の確認を経て、この1件の編集完了を承認した。実際の合成画面では、抽出した代表フレーム、切り替え前後、文字の入口と強調の動きを確認した。

全編の連続再生、ChatCut DesktopからのローカルMP4書き出し、他アカウントでの再現は実施していない。利用者の完了承認を、これらの操作や全条件での再現検証まで済んだ根拠にはしない。次回も、実行した操作と未検証事項を分けて報告する。ローカル書き出しが使えない場合に、有料処理やクラウド書き出しへ無断で切り替えない。
